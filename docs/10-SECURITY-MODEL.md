# Security model

Trusted local administrator, trusted installed plugins, trusted hook executables. Threats: secret disclosure, command injection, repository misidentification, untrusted mounts, privilege escalation by misconfigured hooks, malicious config, stale process claims, accidental destructive admin actions. Out of scope: sandboxing malicious installed Python plugins or defending against root compromise.

No plaintext secrets in config, logs, history, command argv or persisted config snapshots. Use reference-only config, short-lived secret material and secure Restic credential delivery. Validate file secret ownership/mode and reject symlink surprises. Redact known values best-effort from bounded output; disclose limits of redaction. All external commands use argv arrays and explicit environment allowlists. Hooks may intentionally run shells but must be configured explicitly. No automatic unlock/init/approve replacement. Confirm destructive admin operations and log audit events. Protect SQLite and state backups with restrictive permissions. Validate repository ID and physical storage identity before operations. External mounts never released without manager-owned evidence. Unexpected state rollback/corruption blocks automatic execution. Avoid leaking credentials in exceptions and diagnostic JSON.
